# Design notes

## 1. Отмена устаревших запросов

При **каждом** событии `input` `CountrySearchController.onQueryChange()` сначала увеличивает `version`, отменяет подписку текущего запроса через `AbortController.abort()` и очищает старый список. Только после этого запускается debounce. Следовательно, отмена не ждёт, пока задержка закончится. Внутри `CountrySearchRepository` у каждого вызова есть отдельный сигнал подписчика. Если несколько одинаковых поисков используют один сетевой запрос, отмена одной подписки не ломает остальные; сам общий `fetch` отменяется, когда отказался последний подписчик.

`AbortSignal.any([signal, AbortSignal.timeout(10_000)])` объединяет сигнал отмены с таймаутом. `fetch` отклоняет Promise при отмене. В обработчике ошибок `AbortError` игнорируется: это ожидаемое следствие нового ввода/очистки. `TimeoutError` — отдельная настоящая ошибка, которая отображается пользователю с кнопкой повтора. `HttpError` хранит HTTP-статус; 404 переводится в пустой результат, остальные статусы показывают ошибку.

Проверка `version` в `CountrySearchController` оставлена как дополнительная защита: отмена — основное решение гонки, а версия не даёт отобразить ответ, если тестовая/нестандартная реализация транспорта не подчинилась сигналу.

## 2. Задержка debounce

Выбрано **350 мс** в `src/search/country-search-controller.ts`. Такая задержка объединяет последовательный набор букв в один запрос, но обычно не ощущается медленной. Без debounce запрос ушёл бы на каждую букву. При слишком большой задержке, например 1–2 секунды, поиск ощущался бы заторможенным. Сама отмена срабатывает сразу при изменении поля и не зависит от этих 350 мс.

## 3. Сложность алгоритмов

- `mapCountryResponse(raw)` читает фиксированное число полей и перебирает списки языков, валют и границ. Для одного объекта время и дополнительная память — **O(L + C + B)**, где L — число языков, C — валют, B — кодов соседних стран. В реальных ответах эти списки малы; для всего списка стран сложность суммируется по элементам.
- Кэш `CountrySearchRepository` ищет запись в `Map` по нормализованному запросу: в среднем **O(1)**. Хранение занимает **O(S)**, где S — суммарный размер закэшированных ответов. In-flight дедупликация также выполняет поиск по `Map` в среднем за O(1); один ответ/массив разделяется между подписчиками, при этом отмены сигналов изолированы.
- История поиска хранит не более пяти строк; операции над ней ограничены этим лимитом.

## 4. Чистый код и разделение ответственности

- **Одна ответственность на модуль:** `countries.ts` выполняет HTTP-запрос и проверяет статус; `map-country-response.ts` преобразует данные; `country-search-controller.ts` управляет debounce, отменой и состояниями; `app.ts` отвечает за DOM.
- **Чистая функция:** `mapCountryResponse` не зависит от сети, времени или DOM, поэтому проверяется на обычных объектах в unit-тестах.
- **Явные модели:** `Country` и `SearchViewState` находятся в `src/types.ts`; наружу передаются нормализованные поля, а не сырой ответ API.
- **Безопасный вывод:** пользовательские/серверные строки вставляются через `textContent` и `createElement`, динамический `innerHTML` не используется.
- **Обработка ошибок на границах:** сервис отличает HTTP-статус, контроллер различает отмену и сбой, UI показывает подходящее состояние и повторяет последний запрос.
- **Внедрение зависимости в тестах:** контроллер и репозиторий принимают функцию поиска; тесты могут управлять ответом и сигналом без сети.
